# dev-user

Generates the `CLAUDE.md` used by the **dev** user, assembled from a template
plus auto-generated sections.

## How it works

```
CLAUDE.md.blueprint ──────┐
sections/*.md ────────────┼─► build-claude-md.sh ─► CLAUDE.md ─(copy)─► ~/.agents/AGENTS.md
dev-env/sections/*.md ────┘   (dev-env/lib/                     ├─(symlink)─► ~/.claude/CLAUDE.md
      ▲                        build-agents-md.sh)              └─(symlink)─► ~/.dsh/AGENTS.md
      └── dev-env/lib/generate-repo-descriptions.sh (run in phase 1)
```

- **`CLAUDE.md.blueprint`** — the template. Holds the fixed structure/prose and
  a whole-line `{{token}}` for each section to embed. Edit this for layout and
  for workstation-only prose.
- **`sections/`** — this box's sections. `repo-descriptions.md` is generated by
  dev-env's `generate-repo-descriptions.sh`, which lists every repo cloned under
  `/srv/dev/repos` on this box with its GitHub *description* (repo metadata
  fetched from the API — public repos need no auth, private repos use dev's PAT
  from the git credential helper or `gh auth token` at runtime; never hardcoded).
- **`{{shared}}`** — resolved from the sibling `dev-env` repo's
  `sections/shared.md`: the part of the global instructions that is identical on
  every box. Edit it there, not here.
- **`build-claude-md.sh`** — a thin wrapper around the shared engine
  `dev-env/lib/build-agents-md.sh` (also used by the home-server repo). It (1)
  regenerates the generated sections, then (2) expands each `{{token}}` from
  `sections/<name>.md` here, else `dev-env/sections/<name>.md`, and writes
  `CLAUDE.md` atomically. An unresolved token fails the build. If dev-env isn't
  cloned, it keeps the last built `CLAUDE.md`.

## Usage

```bash
./build-claude-md.sh          # regenerate sections + rebuild CLAUDE.md
./build-claude-md.sh --force  # same, re-fetching every repo description
```

Never edit `CLAUDE.md` or generated `sections/*.md` by hand. Edit the blueprint,
or the generators / shared section in dev-env, instead.

## Wiring to dev's global config

`dev-claude-md.sh` installs the built `CLAUDE.md` as `~/.agents/AGENTS.md` (the
neutral agent root) and symlinks both Claude's and the DeepSeek Harness's global
instruction path to it:

```bash
# manual equivalent:
cp /srv/dev/repos/my-system/users/dev/CLAUDE.md ~/.agents/AGENTS.md
ln -sf ~/.agents/AGENTS.md ~/.claude/CLAUDE.md
ln -sf ~/.agents/AGENTS.md ~/.dsh/AGENTS.md
```

## Adding a new section

- **Handwritten, workstation-only:** write `sections/<name>.md` (or just put the
  prose in the blueprint) and add `{{<name>}}` on its own line in the blueprint.
- **Shared by every box:** add it to dev-env's `sections/` instead.
- **Generated:** add the generator to dev-env's `lib/` and register its token in
  phase 1 of `build-agents-md.sh`, then add `{{<name>}}` to the blueprint.
